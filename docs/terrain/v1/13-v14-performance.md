# V1.4 T14.2 性能测量与补丁集锁定

所有数字都在 LM 上测（Windows 11，Intel 20 逻辑核，32 GiB 内存，开始时可用约 16.7 GiB），release 版 processor.exe，运行时 `D:\work\terrain-v1\runtime-v19`（#19 合并后的 master：半像元补丁 + 边缘掩膜补丁，gf-dem-tool 7，清单带补丁集哈希）。测量时 LM 上没有其他构建或测试在跑。原始数据：`docs/terrain/v1/measurements/v14-perf-bench.json`，脚本：`tools/terrain-bench/v14_perf_bench.py`。

## 1. 补丁集锁定

- 处理器编译时内置 CTB 补丁清单（`ctb-half-cell.patch`、`ctb-edge-mask.patch`，按此顺序）。每个补丁取 LF 换行后的 SHA-256，再对按应用顺序排列的 `名字:哈希\n` 取一次 SHA-256，得到补丁集哈希（当前 `fae133b79d33c5d14b7ec97ab0173952b91fdc0b734f2f0bb852404f71521a7f`；#19 合并前只有半像元补丁时是 `b0ed3da9…`）。
- `build-terrain-runtime.ps1` 用同一规则算出哈希，写进清单的 `ctbPatchHashes` 和 `ctbPatchSetSha256`（原来的 `ctbPatches` 名字列表保留）。
- 运行时兼容检查：补丁名字、顺序、单个哈希、整体哈希任一不一致，运行时判为不可用，提示“请用当前 build-terrain-runtime.ps1 重新构建地形运行时”。旧运行时（如 runtime-v12c，只有名字没有哈希）已实测被拒；只有半像元补丁的 runtime-v16 在变基后同样被拒（实测；补丁集和 dem-tool 版本都不同）；runtime-v19 实测可用。
- 能力输出（capabilities）增加 `ctbPatchSetSha256`。
- 断点续跑检查：任务指纹加入 `ctbPatchSetSha256`，换了补丁集的运行时不会接着旧的半成品切。
- 单元测试：补丁名字/顺序/内容不一致都被拒；哈希不受换行影响并和构建脚本规则一致；构建脚本里的 `$CtbPatches` 和处理器内置清单完全一致。

- M：P0 `CTB -g 0.25` 约 12.76 s。现在 auto 下 CTB 阶段 9.51 s，比 P0 快约 25%；单线程 55.9 s。
